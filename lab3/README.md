# Кримзоленд

Документация реализации программной системы аркадного top-down shooter, построенного на `Python + Pygame`.

## 1. Назначение системы

Приложение реализует одиночную игру на выживание с волновой генерацией врагов, несколькими типами оружия, системой очков и таблицей рекордов.

Цели реализации:
- поддерживать устойчивый игровой цикл (`FPS = 60`);
- разделить логику по модулям (ввод, физика столкновений, рендер, волны, хранение рекордов);
- упростить расширение (добавление новых врагов, волн, оружия).

## 2. Технологический стек

- Язык: `Python`
- Библиотека: `pygame`
- Хранение рекордов: локальный JSON-файл `highscore.json`

## 3. Запуск

```bash
pip install -r requirements.txt
python3 main.py
```

## 4. Архитектура системы

Система организована вокруг класса `Game` (`src/game.py`), который управляет состоянием приложения и координирует остальные подсистемы.

### 4.1 Основные модули

- `src/game.py`:
  - инициализация `pygame` и аудио;
  - главный цикл (`run`);
  - переключение состояний игры (`MENU`, `PLAYING`, `PAUSED`, `HIGHSCORES`, `NAME_ENTRY`);
  - обновление игровых сущностей и вызов рендера.
- `src/constants.py`:
  - все константы, enum и dataclass-конфиги;
  - параметры оружия, врагов, UI, дропа аптечек, эффектов смерти.
- `src/input_handler.py`:
  - обработка клавиатурного ввода в зависимости от состояния игры.
- `src/renderer.py`:
  - полная отрисовка сцены, HUD, меню, таблицы рекордов, эффектов.
- `src/collision_system.py`:
  - проверка столкновений пуль/врагов/игрока;
  - расчёт урона и начисления очков.
- `src/wave_manager.py` + `src/waves_config.py`:
  - сценарий волн, очереди спавна, паузы между волнами;
  - сигнал победы после последней волны.
- `src/player.py`, `src/weapon.py`, `src/bullet.py`:
  - модель игрока, переключение оружия, генерация пуль.
- `src/enemy.py`:
  - логика ИИ врага (движение к игроку, стрельба у стрелков/босса).
- `src/pickup.py`:
  - аптечки (время жизни, подбор, восстановление HP).
- `src/score_service.py`:
  - загрузка/сохранение/сортировка таблицы рекордов.

### 4.2 Состояния приложения

Состояния задаются перечислением `GameState`:
- `MENU`: главное меню;
- `PLAYING`: активный игровой процесс;
- `PAUSED`: пауза;
- `HIGHSCORES`: таблица рекордов;
- `NAME_ENTRY`: ввод имени после смерти или победы.

## 5. Игровой цикл

Метод `Game.run()` выполняет цикл:
1. Ограничивает кадр через `clock.tick(FPS)`.
2. Обрабатывает события `pygame` (клавиши, мышь, выход).
3. При `PLAYING` вызывает `update(dt)`:
   - движение игрока и обновление прицела;
   - стрельба игрока;
   - обновление пуль игрока и врага;
   - обновление врагов и их стрельбы;
   - столкновения через `CollisionSystem.handle(...)`;
   - обновление дропа аптечек;
   - обновление волновой системы `WaveManager.update(...)`;
   - проверка поражения/победы.
4. Передаёт текущее состояние в `GameRenderer` для отрисовки.

## 6. Реализация подсистем

### 6.1 Система волн

`WAVE_CONFIG` (`src/waves_config.py`) содержит последовательность `WaveDefinition`:
- состав врагов (`enemy_counts`),
- сложность (`difficulty`),
- интервал спавна (`spawn_interval`),
- признак волны босса (`boss_wave`).

`WaveManager`:
- собирает очередь врагов текущей волны (`build_wave_queue`),
- выдаёт типы врагов для спавна по таймеру,
- завершает волну, когда:
  - очередь пуста,
  - на сцене нет живых врагов,
  - нет вражеских пуль,
- переводит игру к следующей волне или к победе.

### 6.2 Боевая модель

Игрок:
- хранит активное оружие и арсенал стратегий стрельбы;
- ограничивает темп огня `reload_timer`;
- поддерживает переключение оружия (`Q/E`, `1-3`).

Оружие (`src/weapon.py`):
- реализовано через абстракцию `Weapon` и наследников:
  - `AutomaticWeapon`, `ShotgunWeapon`, `SniperWeapon`, `PistolWeapon`.
- фабрика `create_weapon(...)` выбирает реализацию по `WeaponType`.

Враги:
- типы задаются в `ENEMY_TYPES`;
- параметры вычисляются через функции `enemy_hp_for`, `enemy_radius_for`, `enemy_score_for` и др.;
- стрелковые враги генерируют `Bullet` в сторону игрока в пределах дистанции `ENEMY_SHOOT_DISTANCE`.

### 6.3 Столкновения и урон

`CollisionSystem.handle(...)` выполняет:
- контакт враг-игрок (контактный урон);
- попадание пули игрока по врагу;
- попадание вражеской пули по игроку.

Возвращает:
- `score_delta` (прирост очков за уничтоженных врагов),
- `killed_enemies` (координаты и типы врагов для пост-обработки, например дропа аптечки).

### 6.4 Здоровье и аптечки

В `Game.try_spawn_health_pickup(...)` используется вероятность дропа:
- обычные враги: `drop_chance`,
- босс: `boss_drop_chance`.

В `update_health_pickups(...)`:
- уменьшается lifetime аптечки,
- при пересечении радиусов игрок получает лечение,
- HP ограничивается `MAX_HP`.

### 6.5 Таблица рекордов

`ScoreService` поддерживает:
- `load()`:
  - чтение JSON-массива рекордов,
  - совместимость с legacy-форматом (одно число в файле),
  - нормализацию и сортировку по убыванию `score`,
  - ограничение топ-10.
- `add_record(...)`: добавление записи с текущими датой/временем.
- `save(...)`: сохранение топ-10 в `highscore.json`.

Формат записи:

```json
{
  "name": "Player",
  "score": 1234,
  "date": "YYYY-MM-DD",
  "time": "HH:MM:SS"
}
```

## 7. Настройка и расширение

### 7.1 Добавление нового типа врага

1. Добавить новый ключ в `ENEMY_TYPES` (`src/constants.py`).
2. Указать параметры (`hp_mult`, `speed_mult`, `can_shoot` и т.д.).
3. Добавить тип в одну или несколько волн `WAVE_CONFIG`.
4. Опционально подключить изображение `image_path` в `assets/`.

### 7.2 Изменение баланса оружия

Правки выполняются в `WEAPONS` (`src/constants.py`):
- `reload_time`,
- `damage`,
- `bullet_speed`,
- `pellets` и `spread` для дробовика.

### 7.3 Изменение сценария волн

Редактируется `WAVE_CONFIG` в `src/waves_config.py`:
- количество волн определяется длиной `waves`;
- волна босса помечается `boss_wave=True`;
- рост сложности регулируется `difficulty` и `spawn_interval`.

## 8. Управление

- `W/A/S/D` (и RU-аналоги): движение;
- ЛКМ: стрельба;
- `Q/E` или `1-3`: переключение оружия;
- `ESC`: пауза/выход/назад (зависит от состояния);
- `Enter`: подтверждение в меню и вводе имени.

## 9. Ограничения текущей реализации

- Нет сетевого режима и сохранений прогресса между сессиями (кроме рекордов).
- Логика тестируется в основном ручным игровым тестированием.
- ИИ врагов базовый (прямолинейное преследование + простая стрельба).
