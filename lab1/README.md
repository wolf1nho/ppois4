# Программная система «Модель зоопарка»

## Описание
Консольное приложение на Python для управления сущностями зоопарка:
- вольеры и животные;
- сотрудники (ветеринары, экскурсоводы);
- экспозиции;
- экскурсии;
- образовательные мероприятия;
- журнал кормлений и медосмотров.

Система построена в ООП-стиле с разделением на:
- доменные классы (`src/*.py`);
- слой хранения/восстановления состояния (`ZooDataManager`);
- интерфейс взаимодействия с пользователем (`ZooMenu.py`).

## Структура проекта
- `main.py` — точка входа.
- `ZooMenu.py` — консольное меню и пользовательские сценарии.
- `zoo.json` — файл персистентного состояния.
- `src/` — доменная модель и сервисы.
- `tests/` — модульные тесты.

## Доменные сущности
### Базовые сущности
- `Animal` — животное (`name`, `type`, `id`).
- `Enclosure` — вольер (`type`, список `animals`, список `feeds`, `id`).
- `Feed` — запись кормления (`food`, `date`).
- `Visitor` — посетитель (`name`, `birth_year`, `gender`, вычисляемый возраст).

### Персонал
- `Vet` — ветеринар (`name`, `specialisation`, `id`).
- `TourGuide` — экскурсовод (`name`, `languages`, `id`).

### Активности
- `Event` — мероприятие (`name`, `description`, `max_visitors`, `visitors`, `date`).
- `Tour` — экскурсия (`exposition_id`, `tour_guide_id`, `max_visitors`, `visitors`, `date`).
- `Exposition` — экспозиция (`name`, `description`, `enclosure_ids`, `id`).
- `VetLog` — запись медосмотра/лечения (`animal_id`, `vet_id`, `conclusion`, `date`).

### Корневой агрегат
- `Zoo` — центральный объект системы, хранит коллекции всех сущностей и предоставляет операции добавления/удаления/поиска.

## Идентификаторы
`IDGenerator` реализован как singleton-счётчик:
- при создании новых сущностей выдаёт уникальные возрастающие `id`;
- текущее значение счётчика сохраняется в `zoo.json` (`id counter`), затем восстанавливается при загрузке.

## Сериализация
Почти каждая сущность реализует:
- `to_dict()` — преобразование в JSON-совместимую структуру;
- `from_dict()` — восстановление объекта.

`ZooDataManager`:
- `save(zoo)` — собирает полное дерево состояния и пишет JSON;
- `load()` — создаёт `Zoo`, затем последовательно восстанавливает все коллекции.

## Основные сценарии (через `ZooMenu`)
- управление вольерами: добавление/удаление, просмотр животных;
- управление животными: добавление/удаление, кормление, журнал кормлений;
- ветеринарное обслуживание: выбор животного и ветеринара, формирование `VetLog`;
- управление персоналом: ветеринары и экскурсоводы;
- управление экспозициями: создание, добавление/удаление вольеров в экспозиции;
- управление экскурсиями: создание, перенос даты, запись/удаление посетителей;
- управление мероприятиями: создание, перенос даты, запись/удаление посетителей.

## Тестирование
Тесты расположены в `tests/` и покрывают ключевые модули:
- доменные сущности (`Animal`, `Enclosure`, `Event`, `Exposition`, `Tour`, `Visitor` и др.);
- сервисы (`VetService`);
- инфраструктуру (`ZooDataManager`, `IDGenerator`, `Zoo`).

Запуск:
```bash
pytest --cov=src
```
